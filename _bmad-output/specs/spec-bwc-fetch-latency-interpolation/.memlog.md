- (constraint) No server changes; server keeps broadcasting authoritative snapshots exactly as today.
- (constraint) atari/bbc/linux/msdos targets keep loop, fetch path, and rendering byte-identical; all interpolation and instrumentation changes are Amiga-only.
- (constraint) Render clock only ever blends past snapshots; never extrapolate/dead-reckon; u clamps at 1.0 freezing on newest snapshot.
- (constraint) Must not regress the 9-byte ROTATION decode path; rotation rendering itself is deferred.
- (constraint) Instrumentation must not perturb measurements beyond its own display cost.
- (capability) CAP-1 instrumentation overlay: operator sees per-fetch where the ~200ms goes (retry-pause hits, fn_read calls, bytes read, cycle wall time) plus render time, as an on-screen overlay screenshot-readable via the Amiberry drive tooling; stays available behind a runtime flag.
- (capability) CAP-2 fetch latency reduction: dominant cost found by CAP-1 is reduced; success = measured fetch interval improves at least 2x in the same live session, or the review records why the floor is the transport's. Prime suspect: network_retry_pause 2xWaitTOF (~40ms) charged per NOT_READY/zero-byte read round trip.
- (capability) CAP-3 Amiga split loops: Amiga main loop separates fetch from render; render runs WaitTOF-paced ~50fps drawing blended snapshots while fetches continue at transport rate; other targets keep the current single loop unchanged. Requires a shapes-at-positions render entry factored out of show_screen decoupled from app_payload.
- (capability) CAP-4 two-snapshot interpolation engine: prev/curr ShapePos buffers with arrival timestamps filled from bwc_decode_shapes; wrap-aware greedy matcher (equal shapeId, nearest to previous position advanced one packet, copy-to-copy across seams, implausible moves draw snapshot N directly); angle advanced by omega with per-packet resync; stall freezes at u=1.0. Pure parts host-unit-tested in tests/host pattern; smoothness live-verified with before/after captures.
- (decision) Instrumentation is a runtime flag (keyboard-toggleable overlay), not a separate build — ticket states this preference for live A/B comparison in one session; recorded as assumption rather than open question.
