- (direction by user) Create a BMAD spec for fujinet-serial.device so a new session can rewrite it cleanly; include fujinet-nio-serial, tests, why, and context from this work.
- (direction by user) Do not use or mention third-party serial replacements. Keep runtime driver selection (SET_SERIAL / fujinet-nio-serial).
- (direction by user) Amiberry can prove the guest path; hardware (PiStorm) is the acceptance for staying alive after a successful clock.
- (direction by user) The 68040 INTREQ-twice-plus-NOP edit was a guess and did not stop the PiStorm reboot; do not treat it as the design.
- (constraint) Paula UART hardware is the print-validated AHRM extracts under repos/fujinet-nio-driver/docs/amiga/; not the AHRM PDF; not CIA 8520 serial-shift folklore.
- (constraint) Overrun means the prior RX character was not serviced before the next completed. Paula TX and RX are independent; there is no TX-to-RX mode switch.
- (constraint) Do not rename stock serial.device. Default broker backend remains serial.device; fujinet-serial.device is an explicit selection.
- (constraint) Exec interrupt servers may scratch D0-D1/A0-A1 only and return with RTS, not RTE.
- (constraint) Kickstart must not silently rewrite SERPER while FujiNet owns Paula (AddIntServer left ROM on the chain; Amiberry then programmed 9600).
- (constraint) PiStorm/Emu68 is 68040-class; Amiberry a1200-030 passing is not a substitute for the hardware reboot gate.
- (capability) CAP-1 Runtime select the Exec serial driver the broker next opens, without rebuilding the broker.
- (capability) CAP-2 Ship a FujiNet-owned Exec device named fujinet-serial.device that drives Paula as an IOExtSer-compatible serial backend.
- (capability) CAP-3 The broker can complete FujiBus exchanges through that device at 9600, 19200, and 38400.
- (capability) CAP-4 Amiberry case nio-paula-serial proves load, select, clock, and completion marker through fujinet-serial.device.
- (capability) CAP-5 Hardware cold clock one-shot through fujinet-serial.device prints status=0 and returns to the Shell without reboot.
- (capability) CAP-6 Host tests cover SERPER/ring math and SET_SERIAL encode/decode/plan; they do not prove interrupts.
- (note) Pain: stock serial.device is unreliable above 9600 even with ESP 16/2000 pacing; TCP/Amiberry is not Paula.
- (note) SET_SERIAL is FUJINET_NIO_CMD_SET_SERIAL (CMD_NONSTD+3); GET_SERIAL is +4; payload LE unit plus NUL name; fujinet-nio-serial is the CLI.
- (note) Draft tree exists: serial.device sources, install lists, Amiberry nio-paula-serial. Amiberry clock+file-list passed; PiStorm printed status=0 then power-LED reboot.
- (assumption) A clean rewrite may replace the Paula ISR and interrupt-ownership model; it must keep SET_SERIAL, the device name, and the test wiring unless this spec is updated.
- (assumption) 57600 stays out until 38400 is stable on hardware (existing cold/warm procedure).

- (question) Must CMD_READ wait for bytes like stock serial.device, or is QUERY-then-immediate-READ the broker contract?
